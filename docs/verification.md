## Системные разрешения и оставшиеся проверки

### Диагностика отказа от автовставки

`TextInsertion` пишет в системный журнал macOS с subsystem `local.voiceinput.app`
и category `TextInsertion`: наличие поля при начале записи, ошибки AX (числовой код),
роль и доступность изменения атрибутов, совпадение приложения/поля и причину отказа.
Текст диктовки, значения полей, заголовки и URL не записываются. Правила вставки не изменены.
После воспроизведения сбоя в диагностической сборке прочитать последние события:

```sh
/usr/bin/log show --last 10m --style compact --predicate 'subsystem == "local.voiceinput.app" AND category == "TextInsertion"'
```

`paste events posted` означает только отправку Cmd+V; приём текста редактором не подтверждён.

### Захват поля Chromium перед диктовкой

Журнал Яндекс Браузера подтвердил `AXFocusedUIElement: -25212 (kAXErrorNoValue)`
при `trusted=true`; отказ происходил из-за отсутствия исходного поля.
Перед захватом теперь читается роль приложения, а при отсутствующем поле Chromium
получает один запрос `AXEnhancedUserInterface=true`. До записи выполняется до 25
повторных запросов с асинхронным интервалом 100 мс и проверкой исходного приложения
и окна. При отмене запись не начинается; при неудаче остаётся доставка в буфер.
Уже найденное поле не заменяется; правила проверки перед Cmd+V сохранены.

Причина ожидания: [Chromium BrowserCrApplication](https://github.com/chromium/chromium/blob/main/chrome/browser/chrome_browser_application_mac.mm)
откладывает включение расширенной Accessibility на две секунды после запроса.
Это поведение Chromium, а не гарантия реализации в каждой версии Яндекс Браузера.

Автопроверки: 28 проверок жизненного цикла, правил вставки и захвата фокуса проходят,
включая задержанное появление поля, исчерпание попыток, смену контекста и отмену.
Release-компиляция проходит. Живую вставку после холодного запуска Яндекс Браузера
нужно подтвердить диктовкой: сфокусировать поле, нажать горячую клавишу, дождаться
«Слушаю…», произнести короткую фразу и завершить запись. Ожидается вставка в то же
поле; при смене поля — только буфер, при отмене подготовки — отсутствие записи.

После исправления пересобраны подписанные `.app`, ZIP и DMG; `codesign --verify
--deep --strict`, проверка контрольной суммы DMG и `git diff --check` проходят.
Новая `.app` запущена. Computer Use видит редактируемую область в Яндекс Браузере,
но синтетическое нажатие Cmd+Grave не вызвало захват (новых событий в журнале нет).
Поэтому живое исправление и физическая горячая клавиша пока не подтверждены.
Тестовая страница с `data:` URL во встроенном браузере отклонена его политикой URL;
проверка вставки во встроенном браузере также не выполнена.

Доступ к микрофону и Accessibility был подтверждён в предыдущей ad-hoc сборке.
Причина рассогласования переключателя macOS и приложения подтверждена журналом TCC:
сохранённое code requirement не совпадало с cdhash пересобранного приложения.
Адресный сброс `tccutil reset Accessibility local.voiceinput.app` и новое разрешение
устранили проблему; оба индикатора приложения показывают доступ.

Автоматически отправленное через Computer Use сочетание в TextEdit не дало
наблюдаемого запуска записи. Это не подтверждает ни исправность, ни неисправность
физической глобальной клавиши: нужна проверка реальным нажатием пользователя.

Не проверены end-to-end: физическая клавиша в обеих раскладках, запись/индикатор уровня,
вставка в TextEdit и встроенный браузер Codex, буфер при смене фокуса,
отмена во время реальной записи/распознавания и отключение микрофона.
Ожидается: два нажатия Cmd + физическая клавиша ` запускают и завершают запись;
исходное активное поле получает текст, при смене поля доступна только копия в буфере;
отмена не вставляет текст.

## Контекст пунктуации

SpeechEngine передаёт русский образец оформления в promptTokens. Для WhisperKit 1.0
исключены специальные токены из образца, ранний EOS во время prefill подавляется
через SuppressBlankFilter; проверка вероятности первого токена контекста отключена.
Без этой защиты тест возвращал пустой текст. После первого токена речи EOS разрешён.

Проверены две синтетические русские записи: 8,02 и 58,95 секунды. Слова сохранены
(с учётом ё/е), образец не попал в результат. Минутная запись распознана за 5,74 с
без учёта загрузки модели. Пунктуация на этих примерах совпала с исходной версией;
доказанного улучшения на живой диктовке пока нет. Образец — мягкая подсказка,
а не отдельный корректор. Release-сборка и 21 проверка состояний/вставки проходят.

## DMG

Release-сборка создаёт Voice-Input-1.0.0-arm64.dmg. Проверены контрольная сумма
(hdiutil verify), монтирование только для чтения, arm64-бинарник и подпись .app
внутри образа. Ссылка «Программы» ведёт в /Applications; текстовых инструкций в образе нет.
Окно Finder 540 × 300: Voice Input слева, стрелка на Retina-фоне, «Программы» справа.
Расположение проверено визуально в Finder. Сборщик также монтирует готовый DMG только
для чтения и проверяет подпись вложенного приложения и цель ссылки до замены артефакта.
Установка на другом Mac с Gatekeeper
не проверена; пользователь должен скопировать .app в «Программы», разрешить запуск
доверенной копии и пройти первоначальную подготовку.
